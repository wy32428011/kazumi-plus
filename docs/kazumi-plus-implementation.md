## 数据与能力边界

动漫继续使用原有 Hive 模型和同步服务。影视使用 `plus_source_collections_v1`、`plus_source_histories_v1`、`plus_source_progress_v1` 与 `plus_media_preferences_v1`；记录保存完整来源身份和摘要快照。数据库主键是完整身份的 SHA256 编码，防止长详情 URL 超过 Hive 主键长度限制；没有使用标题生成身份。

独立版初次使用新数据目录，不扫描原版库。原规则可导入；完整旧数据迁移不在首版范围。动漫 WebDAV 根目录为 `/kazumiPlusSync`，影视数据暂不上传。

影视播放器复用 `PlayerPlaybackController` 和 media-kit；不构造伪造 Bangumi 条目。HLS/直接媒体由内核打开，播放页面通过已有 WebView 解析。来源季信息缺失时保留未分季状态，进度按照作品、季、线路和播放项分别保存。

## 运行发现与修复

1. 首次 Windows 窗口隐藏：恢复首帧显示，并使用独立窗口类和互斥标识。首次引导由独立完成标记管理，影视种子规则不再跳过内置动漫规则安装。
2. Android 模拟器默认硬解 ANR：本应用显式传入自动解码选项，绕过锁定 media-kit 分支的模拟器判断。同片关闭硬解对照出画后，影视默认自动模式改为平台选择；真机和用户显式解码设置保留。新包恢复硬解开/auto-safe后两类视频实际出画，无新增 ANR。
3. Android 首集升级续播曾回零：锁定分支在输出尺寸变化时再次按异步位置进行补偿 seek。影视恢复改为初始化后进入同一输出锁、显式定位、实际 time-pos 回读，确认前不保存零位；切集/返回可取消，等待锁及定位均有超时。最新APK用第1集04:16实际记录初始恢复成功并推进至04:44，但随后跨插播低PTS会覆盖进度，不能混为同一初始化问题或声称完整修复。
4. My 页摘要只统计动漫：动漫统计保持原语义，影视历史按真实条目独立计数；统一入口监听两个通知源，不推算累计观看时长。
5. 来源失效样本：Love or Not 的第1集地址返回404，保留失败提示与证据，没有计为播放通过。来源清单可达不保证每个历史作品资源可用。

Android 原始验收汇总在 `.tools/logs/android-acceptance/summary.json`，逐步记录在 `acceptance.jsonl`；后续最新包的限定回归单独记录，旧 APK/旧失败日志不替换为新结论。arm64 release使用调试证书签名，已做构建、ABI及签名回读，未在真机运行。
