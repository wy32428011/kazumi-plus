# 电影与电视剧来源扩充计划

日期：2026-10-12。状态：接入、媒体链核验、增量安装回读及两端构建交付完成。

## 需求与接入边界

- 在现有暴风影视之外增加多个实际可访问的电影、电视剧来源，优先采用与当前引擎兼容的公开 JSON 接口。
- 沿用 `plusSchemaVersion: 1`、稳定 `ruleId`、分类白名单、资料规则和分隔字符串选集机制。不同站点独立保存编号和分类，不根据分类名称猜测编号。
- 接入完整分类、分页浏览、搜索、详情与剧集播放入口；优先选择直接提供 HLS 地址的接口，避免接入必须额外解析网页的线路。
- 已使用旧版的用户升级后可获得新增来源，同时保留已有来源、用户的禁用状态和删除决定。已有自定义规则不得覆盖。
- 保留工作区原有改动，更新 README 和影视规则说明。按用户要求不新增或运行自动化测试；通过实际请求、规则解析、编译和产物回读验证。

## 分工与实施顺序

1. 并行审阅现有接入链路、调研来源官网/API和分类结构。
2. 对候选源核实电影和电视剧分类、至少一项详情、剧集地址、搜索与分页；剔除失效或不兼容源。
3. 为通过核实的来源增加独立 JSON 规则，并实现逐来源的一次性安装记录，兼容原 `plus_seed_v1.json`。
4. 使用现有解析器验证规则和真实响应；检查安装记录、重复编号和频道边界；编译 Windows 和 Android 交付包。
5. 回读构建产物和校验值，更新文档，明确区分 API/清单可达与播放器音画验收。

## 验收标准

- 新来源在电视和电影频道均具有明确的分类白名单及有效默认分类。
- 真实 API 返回的标题、站内编号、海报、详情和剧集可被当前引擎解析；选集地址可以读取 HLS 清单及样本分片。
- 新安装和持有旧安装记录的用户均能收到新来源；再次启动不会重新安装已删除的新来源，不启用被用户禁用的规则。
- 规则文件随 Flutter 资源打包；交付包中可回读新增规则，说明文档与实际新增名单一致。
- 失败来源和未做的音画验证如实记录，不因 JSON 返回 HTTP 200 就声称全部影片均可播放。

## 调整记录

- 速播、魔都、光速已用项目现有解析器完成真实分类、分页、搜索、详情、选集及媒体链核验。
- 索尼目录和媒体链可访问，但关键词搜索返回纯文本“暂不支持搜索”，不符合完整接入要求，剔除规则并改查高清影视（1080）。
- 量子抽查媒体清单返回 404；无尽媒体/搜索遭遇 403；非凡 HTTPS 发生 TLS 连接失败，均不默认加入。
- 高清1080的分类、搜索与详情可用，但多个新旧影视清单均403，剔除；最终新增速播、魔都、光速，连同暴风共4个来源。

## 完成证据

- 三个新增来源均通过现有解析器的双频道分类、目录两页、搜索、详情、选集及HLS/密钥/分片抽样核验。
- 代码及规则经独立代理交叉审查；定向静态分析无问题；没有新增或运行自动化测试。
- Windows新版实际启动后回读四个来源及累计安装标记，原暴风规则JSON保持一致。
- Windows和Android arm64最终Release构建成功；ZIP和APK内置规则已回读，交付物校验值已生成。
- README与规则文档已更新；详细结果见 [来源扩充记录](media-sources-2026-10-12.md)。新增来源未逐一做播放器音画及Android真机验收，不将媒体链抽样描述为全库播放保证。
